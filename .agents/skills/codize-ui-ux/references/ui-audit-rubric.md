# Codize V2 UI audit rubric

## Authority and scope

- Is the audited surface V2 work or current V1 maintenance?
- Are Product Thesis, Exact UX, Character Blueprint, and Figma roles respected?
- Does any V1 mechanic appear as a future requirement without authority?
- Does the UI invent unresolved backend or learner-state behavior?

## Student goal and next action

- Can a beginner identify the current change and next action immediately?
- Is there one primary cognitive task and one dominant action?
- Is the build plan secondary rather than an always-expanded curriculum?
- Can the student choose another direction or recover?

## Conversation and teaching

- Is Build orchestrated rather than generic chat?
- Does Codize ask, teach, hint, or stay quiet appropriately?
- Is Need Help accessible and non-punitive?
- Are redundant questions skipped when the behavior is already present?
- Can support visibly fade without hiding important safety checks?

## Truth and agency

- Are student claims, agent claims, repository facts, inference, checks, and evidence distinct?
- Is uncertainty visible?
- Does the student retain consequential decisions?
- Are correctness, security, verification, and mastery claims supportable?

## States and recovery

- Are empty, loading, saved, error, retry, incomplete, complete, stale, and recovery states covered where applicable?
- Is student work preserved across recoverable failure?
- Does Something broke investigate before another patch?

## Information architecture

- Are Project / Build / Learning / History primary and Character / Settings secondary?
- Is Something broke contextual?
- Are internal phases, gates, archetypes, provenance ontology, and routine Defense hidden unless maintaining V1?

## Character and motion

- Is character prominence appropriate to the surface?
- Is dialogue available as text and meaning independent of expression/sound?
- Are motion and sound optional with reduced-motion equivalents?
- Do celebrations match known accomplishments rather than trivial clicks?

## Accessibility and responsive behavior

- Semantic headings, labels, controls, keyboard flow, visible focus, status announcements, contrast, and text alternatives.
- Mobile uses progressive disclosure rather than tiny text.
- Long paths, code, errors, localization, and user content wrap or scroll safely.
- Code/diff views remain navigable.

## Visual composition

- Does the implementation match approved Figma for hierarchy, spacing, component appearance, responsive layout, and motion intent?
- Are deviations explicit and behavior-preserving?
- Does polish support comprehension instead of creating attention competition?

Classify findings as confirmed defect, likely improvement, or subjective preference. Give evidence, impact, smallest safe fix, and verification.
