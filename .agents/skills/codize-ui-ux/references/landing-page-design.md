# V2 landing-page design

The canonical landing story comes from the Product Thesis and Exact UX Specification; approved Figma controls composition.

## Required story

- Hero promise: **Build something real with AI. Learn how it works as you go.**
- Explain the gap between project growth and student understanding without fake percentages.
- Show that Codize works around the external coding agent rather than replacing it.
- Present a better path: one change, one useful thing, build with AI, check what happened, keep building.
- Explain recovery as stopping the patch loop and investigating.
- Make the character prominent but never necessary for understanding content.
- Keep the primary CTA obvious and avoid feature-card overload.

## Avoid

- leading only with the 80% Trap;
- shaming AI use;
- presenting Project Defense or the visible V1 Build Loop as the product;
- claiming measured learning outcomes without evidence;
- school-dashboard, generic SaaS, or fake-IDE framing;
- motion that competes with comprehension or ignores reduced motion;
- multiple equal CTAs.

Use V1 landing code only as current implementation evidence. It is not V2 visual or behavioral authority.
