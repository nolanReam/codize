# Codize Pilot UX Lessons

> [!NOTE]
> **Historical V1 pilot evidence.** Reuse observed cognitive-load, accessibility, draft-preservation, and truthfulness lessons where they remain relevant. Do not preserve V1 Project Defense, phase, progress, or workflow UI merely because it appears here.

## Observed problems

- Dashboard initially felt overwhelming.
- Too much visible instructional text made pages feel like homework.
- Users did not always know where to look first.
- Prompt Builder was useful but initially required too much interpretation.
- Evidence felt complicated.
- Project Defense felt strict without enough preparation framing.
- Wide monitors exposed unused space.
- Users confused build-task progress with workflow progress.
- Users expected unsaved work to survive navigation.

## Product lessons

- Guidance should be contextual and progressively disclosed.
- Every state should have one obvious next action.
- UI should communicate relationships instead of explaining every relationship in prose.
- Examples and starter choices reduce blank-page friction.
- System state must remain visible.
- The interface should preserve uncertainty rather than force false confidence.
- Wide layouts should use space intentionally without making reading lines excessively long.
